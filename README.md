# Audio Daily Digest

Daily news digest: scrape RSS sources, summarize into a spoken-style script via an LLM,
synthesize speech, and serve it through a small API + frontend (plus optional Telegram push).

See `CLAUDE.md` for the full project context.

## Run it (Docker)

```bash
cp .env.example .env   # fill in ANTHROPIC_API_KEY, API_KEY, etc.
docker compose up --build
```

Frontend + API are served from a single container at `http://localhost:8000`.

## Run it locally without Docker

```bash
cp .env.example .env
uv sync
uv run uvicorn audio_digest.api.app:app --app-dir backend/src --reload
```

## API

Interactive docs (Swagger UI) are auto-generated by FastAPI at `/docs`, raw schema at
`/openapi.json`. Summary of the endpoints:

- `GET /api/digest/today` — today's digest as JSON (script, segments, tone, timings)
- `GET /api/digest/today/text` — today's digest as plain-text newsletter copy
- `GET /api/digest/today/audio` — today's digest MP3
- `POST /api/trigger-digest` (header `X-API-Key: <API_KEY>`) — trigger a new run in the
  background; intended to be called by cron/a scheduler rather than a user

The read endpoints (`/today`, `/today/text`, `/today/audio`) are public and unauthenticated —
the frontend is meant to be a shareable public page. Visiting it with `?demo` in the URL hides
content-selection controls (e.g. the tag filter), for sharing a read-only link.

## Configuration

All configuration is via environment variables / `.env` — see `.env.example` for the full list
with comments. No runtime settings UI by design; changing behavior means editing `.env` and
restarting.

Summarizer provider is set via `SUMMARIZER_PROVIDER`:

- `claude` (default) — needs `ANTHROPIC_API_KEY`
- `openrouter` — needs `OPENROUTER_API_KEY` ([openrouter.ai/keys](https://openrouter.ai/keys)); model is configurable via
  `OPENROUTER_MODEL` (default `google/gemini-2.5-flash`), see the [model catalog](https://openrouter.ai/models)
  for alternatives — pick one with structured-output support


## First-time Telegram setup (optional)

1. Create a bot via [@BotFather](https://t.me/BotFather), copy its token into `TELEGRAM_BOT_TOKEN`.
2. Send the bot any message, then visit `https://api.telegram.org/bot<token>/getUpdates`
   to find your numeric `chat_id`, and set `TELEGRAM_CHAT_ID`.
3. Each digest run sends the newsletter text as a message, followed by the audio file.

## Tests

```bash

uv run ruff check .
uv run ruff format --check .
uv run mypy backend/src
```

CI (`.github/workflows/ci.yml`) runs all of the above plus a Docker build on every push/PR;
`build-and-push.yml` publishes the image to GHCR on pushes to `main`.
